# 設定リファレンス: 変えるとどうなる「はず」か / 作者が体感したこと

設定は `~/.config/betterframe-xp/params.conf`（`key = value`）。0.25 秒ごとに読み直すので、SteamVR の再起動は要らない。範囲外の値は範囲内にクランプされる。

## この文書の読み方

設定ごとに、次の 3 つを**分けて**書く。

| 列 | 中身 | 信用できる度合い |
|---|---|---|
| 変えるとこうなる「はず」 | 計算式やコードの作りから言えること | **予想**。ヘッドセット内では確かめていない |
| 作者が体感したこと | 作者（1 人、Frame 1 台）が実際に見て、または測って確かめたこと | その環境でだけの話。他の人で同じとは限らない |
| 負荷 | レイヤーの GPU 時間への影響 | 測ったものは数字を書く。測っていないものは「測っていない」と書く |

「はず」の列は、他の人が試したときの目安として読んでほしい。**作者が体感できていないものは「体感できていない」と書く。** 体感できていない = 効果が無い、ではない（見分けにくいだけかもしれない）。

> 作者の Frame で、レイヤーの GPU 時間は 144 Hz の 1 フレーム 6.94 ms のうち、シャープ有りで約 1.4 ms（約 2 割）。

「ガクッ」が何の現象を指すかは [STUTTER.md](STUTTER.md) にまとめた。原因の違う 5 種類があり、このツールが関係するのは主に 1 種類。

## まず使うもの（3 つ）

| キー | 範囲 / 既定 | 変えるとこうなる「はず」 | 作者が体感したこと | 負荷 |
|---|---|---|---|---|
| `enabled` | 0/1 / 1 | 0 にすると全部の効果が止まり、映像は素通しになる（レイヤー自体は残る） | 効くことを確認した | 0 のときは「コピーだけ」の経路。約 0.3〜0.6 ms |
| `streamOnly` | 0/1 / **1** | 1 だと、PC の映像が出ているフレームだけに効果が掛かる。ホーム・ダッシュボード・読み込み画面は素通し。映像の上に重なる UI は同じフレームなので一緒に掛かる。0 だと全フレームに掛かる（映像の検出が外れたときの逃げ道）。**0 にすると Frame 単体（PC につなげていないホーム）にも掛かるが、その状態でダッシュボードを選ぶと映像が乱れる（作者の報告。どの条件でも出るかは未確認）** | 「効果は映像にだけ掛かり、鮮明さは変わらなかった」。ホームで頭を振ったときのガクッが多少減った | 映像が無いフレームは「コピーだけ」になり、約 0.3〜0.6 ms |
| `sharpenAmount` | 0〜2 / 1.2 | 上げるほどシャープが強くなる。0 で無効。1 を超えると、縁に白黒の縁取り（リンギング）が出やすい。失われた細部は作れない（超解像ではない） | 映像に掛かることは確認した。**効果は体感できる**。量ごとの見た目の比較は記録が薄い | **強さを上げても負荷は増えない「はず」**（強さは最後の掛け算に使うだけで、読む画素も計算の量も同じ）。負荷が変わるのは 0 か、0 より大きいかだけ。強さを変えての測定はしていない。ただし作者の体感では「強めの設定ほどガクッとなりやすい」で、式のうえの予想と**食い違っている（未解決）**。強さを上げて引っかかりが増えたら下げてほしい。詳しくは [STUTTER.md](STUTTER.md) の A-3。 |

## シャープの形を決めるもの

| キー | 範囲 / 既定 | 変えるとこうなる「はず」 | 作者が体感したこと | 負荷 |
|---|---|---|---|---|
| `sharpness` | 0〜1 / 0.7 | 上げるほどシャープの掛かり方が積極的になる。ノイズも目立ちやすくなる | 見た目の評価なし | 変わらない「はず」（式の係数が変わるだけ）。測っていない |
| `centerRadius` | 0〜1 / 0.55 | 各目の画像の**真ん中**から、この半径（目の半径に対する割合）までは全力で掛かる。小さくするほど、全力の範囲が狭くなる。**視線は使っていない**ので、目玉を動かしても強い場所は動かない | 見た目の評価なし（体感の記録がない） | 変わらない「はず」（掛ける強さが位置で変わるだけ）。測っていない |
| `edgeAmount` | 0〜1 / 0.4 | 目の縁での強さの割合。0 で縁はシャープが掛からず、1 で全体が同じ強さ。**`centerRadius = 1` のままだと、強さが下がり始めるのは目の半径の 0.95 のあたりからで、変わるのは画像の四隅と縁だけ**（レンズ越しにはほとんど見えない）。違いを見るには `centerRadius` を 0.3 前後に下げる | 見た目の評価なし。0 と 1 で切り替えても違いが分からなかったという報告がある（作者の Frame の設定は `centerRadius = 1` で、この組み合わせでは式のうえでも変わるのは四隅だけ） | 変わらない「はず」。測っていない |
| `showSplit` | 0/1 / 0 | 各目の中央に縦線（白 3 px + 両側に黒 3 px）が出て、線の左は素通し、右は処理後になる。**確認用** | 見比べるための機能。効果の評価ではない | 線を描くぶんだけ。測っていない |

## 軽くするためのもの（既定のままでよい）

元の CAS は 3×3 の 9 点を色ごとに計算する。次の 3 つで軽くしてある。

| キー | 範囲 / 既定 | 0 のとき | 1 のとき（既定） | 作者が体感したこと |
|---|---|---|---|---|
| `casCross` | 0/1 / 1 | 3×3 の 9 点 | 十字の 5 点 | 個別の評価なし。案 1+2（`casCross` と `casLuma`）だけでは違いが分からなかった |
| `casLuma` | 0/1 / 1 | 色ごとに計算 | 明るさ 1 つで全色に | 個別の評価なし |
| `cornerSkip` | 0〜2 / 1.15 | 四隅も処理 | 目の半径の 1.15 倍より外は素通し（内接円の外） | 3 つ込みで「だいぶ安定した」。3 つの個別の寄与は分かっていない |

- **変えるとこうなる「はず」**: 3 つを ON にするほど軽くなり、見た目はほとんど変わらない。四隅の効果は弱いと作者が判断して省いている。3 つとも 0 にすると、元の 3×3 RGB の CAS と同じ式になる。
- **負荷（測定済み）**: レイヤーの GPU 時間（シャープ 1.2）は、元の CAS **1.42 ms** → 3 つとも ON で **0.98 ms**。3 つの個別の寄与は測っていない。
- 見た目が変わるかどうかは、3 つとも ON/OFF を比べた記録がない。

## 実験的な機能（パネルの「実験的」タブ。既定は全部オフ）

見た目も負荷も、個別に評価した記録がない。使ってみて良ければ、結果を教えてほしい。

| キー | 範囲 / 既定 | 変えるとこうなる「はず」 | 作者が体感したこと | 負荷 |
|---|---|---|---|---|
| `debandAmount` | 0〜1 / 0 | 暗部や空にできる色の段差（帯）がなめらかになる。4 点のぼかし + ディザ。エッジや模様のある所は変わらない。**調整すると映像が乱れる不具合がある（作者の報告。条件・原因は未調査）。乱れたら 0 に戻す** | 個別の評価なし | 増える「はず」（読む画素が増える）。増えた分は測っていない |
| `debandRange` | 1〜32 px / 12 | 大きいほど広い範囲でなめらかにする | 個別の評価なし | 範囲によらない「はず」。測っていない |
| `debandThreshold` | 0.5〜8 / 2.5 | 大きいほど、色差のある所までなめらかにする（8 ビット換算）。大きすぎると細かい模様がぼやける | 個別の評価なし | 測っていない |
| `detailBoost` | 0〜1 / 0 | 「模様が少し残る所」（草・地面）だけ最大 2 倍強く、平らな所と強い輪郭は 0.25 倍にする | 作者の「良い版」は 0.8 で運用していたが、見た目の個別評価はない | 追加の読み取りは無い「はず」（シャープの計算で出したコントラストを使う）。測っていない |
| `grainAmount` | 0〜1 / 0 | 明るさだけに細かい粒が乗り、圧縮ののっぺり感が目立たなくなる。強い輪郭には乗らない | 個別の評価なし | 増える「はず」。測っていない |
| `grainSize` | 1〜4 px / 1 | 粒が大きくなる | 個別の評価なし | 測っていない |
| `grainAnimate` | 0/1 / 1 | 1 は毎フレーム粒が変わる（64 通りで循環）。0 は固定 | VR では、固定だと「顔に貼り付いて」見え、動かすとちらつきに見えることがある | 変わらない「はず」 |

## 色調整（パネルの「色調整」タブ。1.0 で変化なし）

シャープ・デバンド・グレインのあとで、最終的な画面の色を整える。**5 つとも 1.0 のときは着色器がこの段落を飛ばす**（レイヤーは素通しコピーのまま）。色調整は「目の中心の重み」の影響を受けず、目全体に均一に掛かる。

| キー | 範囲 / 既定 | 変えると「はず」 | 作者の体感 | 負荷 |
|---|---|---|---|---|
| `contrast` | 0.5〜1.5 / 1.0 | 中間グレーを軸に明暗の差を変える。1 より大きいと硬調、小さいと平坦 | 新規。未評価 | 「はず」ほぼ増えない（1 画素 1 回の積和） |
| `saturation` | 0〜2 / 1.0 | 輝度と混ぜる。0 で白黒、1 より大きいと鮮やか | 同上 | 同上 |
| `gamma` | 0.5〜2.5 / 1.0 | 出力を `pow(c, 1 / gamma)` する。1 より大きいと中間調が持ち上がる | 同上 | 1.0 以外のときだけ 1 画素 2 回の `pow` |
| `temperature` | 0.8〜1.2 / 1.0 | RGB ゲイン `(t, 1, 1/t)` を輝度で正規化する。暖色・寒色に寄せても明るさは変わらない | 同上 | ごくわずか |
| `brightness` | 0.5〜1.5 / 1.0 | 最後に全体へ掛ける（ガンマのあと） | 同上 | ごくわずか |

ショートカット（この 5 つだけを変える）:

| ショートカット | `contrast` | `saturation` | `gamma` | `temperature` | `brightness` |
|---|---|---|---|---|---|
| ニュートラル | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| ビビッド | 1.03 | 1.10 | 1.01 | 1.01 | 1.01 |
| ソフト | 0.95 | 0.90 | 1.05 | 1.00 | 0.98 |
| アイケア（暖色） | 1.05 | 1.10 | 1.00 | 1.05 | 1.00 |

## 視線の補正（SteamVR の設定。`params.conf` には書かない）

パネルの「SteamVR 設定」タブで、Frame のアイトラッキングの補正 2 つをオン/オフする。シャープとは別の機能で、レイヤーは関係しない。SteamVR 自体の設定を書き換えるのはこのタブだけ。

| スイッチ | SteamVR の設定 | 内容 | OFF にするとどうなるか（パネルの Tips） |
|---|---|---|---|
| 奥行きの補正 | `steamvr.gazeDepReprojectEnable` | 「視線認識型の再投影」。フルレートが出ていないときのカクつきを減らす（Valve の説明） | 視界の端を見ながら頭を動かしたときのガクつきが減る。作者の環境で一番効いた変更で、デメリットは作者は感じていない |
| 目の位置の補正 | `steamvr.gazeDepEyeToHeadEnable` | 「瞳孔位置補正」に当たると思われる（確定ではない）。眼球の回転に合わせて、映像を作るときの目の位置をずらす | 頭を動かしたときのガクつきが減る。奥行きと一緒に OFF にして安定した（単独の効果は切り分けていない）。OFF は Valve の既定値と同じ |

- どちらも Valve が SteamVR の設定画面から外した項目。裏の設定として今も効く。
- 作者の環境では、**オンのままだと視界の端を見ながら頭を動かしたときに揺れ、オフにしたら体感が良くなった**。ただし 1 人・1 台の体感で、他の環境で同じとは限らない。揺れを感じたときに比べるための切り替え。
- 保存先: Frame の `~/.config/openvr/config/steamvr.vrsettings`（`steamvr` セクション）。パネルは、スイッチを押したときだけ `IVRSettings::SetBool` で書く（`vrcmd --set-settings-bool` と同じ）。押さなければ何も書かない。
- 初期値が値と同じになると、SteamVR がユーザー設定ファイルからキーを消すことがある（作者の環境で `gazeDepEyeToHeadEnable` がそうなっていた）。ファイルに無いのは異常ではない。パネルは SteamVR に聞いた値を出す。
- すぐ効くかは未確定。効かなければ SteamVR を再起動する。パネルは再起動しない。
- **最初の値の記録**: 最初に切り替える直前の値を、`~/.config/betterframe-xp/gaze-before.conf`（`key = 1/0`）に一度だけ残す（パネルも `betterframectl gaze` も同じファイル）。2 回目以降は上書きしない。残せなかったときは SteamVR の設定を書かない。
- 戻し方: `betterframectl uninstall`（記録した値に戻してから削除）。個別には、パネルで押し直す、`betterframectl gaze reproj on`、または `vrcmd --set-settings-bool steamvr.gazeDepReprojectEnable 1`（値は 1 / 0。`true` は 0 と読まれる）。手動の方法は README の「視線の補正を手で切り替える」。
- 記録の値は「そのときの有効値」（SteamVR に聞いた値）。ユーザー設定ファイルにキーが無かった場合も、ドライバーの初期値が記録される。戻すときは、その値を明示的に書く（キーを消して初期値に戻すのではない）。初期値と同じ値を書けば、SteamVR がファイルからキーを消すこともある。
- SteamVR につながっていないときは「読めません」と出てスイッチは効かない。値は 3 秒おきと、パネルが見え始めたときに読み直す（外から変えられても追いつく）。

## 設定を変えたあとの確認

- `betterframectl stats`（またはパネル）で `gpuMsAvg` を見る。`streamOnly = 1` なら、映像が出ている間は約 1.4 ms（運用値）、無い間は 0.3〜0.6 ms 程度になる。
- 映像が出ているのに `gpuMsAvg` が 0.6 ms 前後のままなら、映像を検出できていない。`$XDG_RUNTIME_DIR/betterframe-xp.log` に `PC video on screen: effects on` / `gone: effects off` が出ているか見る。出ていなければ `streamOnly = 0` に戻す。

## パネルのタブと、設定の整理

| タブ | 中身 |
|---|---|
| 画質 | 段落ごとに分けてある。**シャープ**: `sharpenAmount`（主）。その下に副設定として `sharpness` と、シャープの方式 `casCross` `casLuma` `cornerSkip`（`casCross` `casLuma` `cornerSkip` は軽量化）。副設定は `sharpenAmount` が 0 のときは効かない。**中心の重み**: `centerRadius` `edgeAmount`。**プリセット**（標準 / 弱め / 効果なし）。右上のヘッダーに `enabled` `showSplit` `streamOnly` |
| 色調整 | 5 つのスライダー（`contrast` `saturation` `gamma` `temperature` `brightness`）とショートカット（ニュートラル / ビビッド / ソフト / アイケア）。**シャープのあとに最終画面へ掛かる。中心の重みの影響を受けない** |
| 実験的 | 段落ごとに分けてある。デバンド（主: `debandAmount`、副: `debandRange` `debandThreshold`）/ シャープの補助（`detailBoost`。画質タブの `sharpenAmount` が 0 だと効かない）/ グレイン（主: `grainAmount`、副: `grainSize` `grainAnimate`）。プリセット（暗部重視 / 草・地面）。3 つの効果とも「中心の重み」で周辺ほど弱まる |
| SteamVR 設定 | Frame の SteamVR の設定である、視線の補正（奥行き / 目の位置）と、それぞれの Tips。**SteamVR 自体の設定を書き換えるのはこのタブだけ** |
| 更新 | いまの版 / 最新の版、「今すぐ確認」「この版に更新する」、1 時間ごとの自動確認のスイッチ（`updateAutoCheck`、既定 ON。パネルだけが使う設定で、レイヤーは読まない）。仕組みは [GUIDE の更新の節](GUIDE.md#更新パネルから) |

- 「SteamVR の再起動が必要」の帯は設定ではなく状態の表示。レイヤーを有効にしてあるのに vrcompositor が読んでいない、または読んでいるのが入れ替え前の古いファイル、のときに出る。SteamVR が動いていないときは出ない。
- `pcvrOnly` は廃止した（`streamOnly` に置き換わったため）。`params.conf` に残っていても無視される。
- `splitEyes` は公開する設定から外した。Frame の画像は常に左右 2 つの目が並ぶので、レイヤーの内部の既定値（1）のまま使う。`params.conf` に書けば今も読むが、変える理由はない。
- パネルの大きさ: 画像 1200×888 px を、ダッシュボードで幅 2.0 m に出す（以前は 1200×1238 px を 2.8 m で、高さが約 2.9 m あった）。
- `showSplit` は、各目の中央に縦線（白 3 px + 両側に黒 3 px）を引く。線の左は素通し、右は処理後。
- 既定は運用値（`sharpenAmount 1.2`、`sharpness 0.7`、`centerRadius 0.55`、`edgeAmount 0.4`、`streamOnly 1`）。
- 分類の理由: 効果が確認できたのはシャープだけで、それ以外は見た目の個別評価がない。
